# Оргскоп — ИИ-агент «Анализ организационной структуры и функционала»

## Краткое описание

При реорганизации подразделений сотрудник вручную сравнивает оргструктуры, положения о подразделениях и приложения к распорядительным документам. Так легко пропустить потерю функции, дублирование или конфликт интересов.

Агент принимает документы «до» и «после» реорганизации и сам определяет, какие подразделения созданы, сохранены или упразднены. Он сопоставляет функции, находит потери, дублирование и потенциальные конфликты интересов. К каждой находке прилагается ссылка на пункт документа и цитата.

## Что реализовано

- Загрузка документов Word, PDF и Excel через веб-интерфейс или из командной строки.
- Нарезка документа на пункты и атомарные функции. Автонумерация и стили Word не нужны: учитываются склеенные пункты, даты и ссылки вида «п. 5.3».
- Реестр подразделений и должностей из раздела «Структура». По нему определяется, что создано, сохранено, упразднено или переименовано. Этот шаг детерминированный, без LLM.
- Выравнивание пунктов двух редакций по содержанию, поэтому сдвиг нумерации не мешает сравнению.
- Сопоставление функций по владельцам. Статусы: сохранена, изменена, перенесена к другому подразделению, не найдена, новая.
- LLM-анализ:
  - классификация изменённых пунктов на редакционные и смысловые;
  - **агент** проверяет каждого «кандидата в потерю»: ищет функцию в новой редакции своим инструментом `search_new_edition` и выносит вердикт;
  - поиск дублирования функций и конфликтов интересов;
  - итоговый вывод и рекомендации со ссылками на номера находок.
- **Проверка ссылок.** Каждый пункт и цитата, которые вернула модель, сверяются с документом. Неподтверждённые находки отбрасываются или помечаются. Если модель ошиблась номером, пункт находится по цитате.
- Отчёты в Excel (листы по разделам «Выхода» из ТЗ) и HTML.
- Офлайн-режим без ключа: работает вся детерминированная часть.

## Как работает решение

1. Пользователь загружает документы «до» и «после» (или выбирает тестовый набор).
2. Парсер нарезает каждый документ на пункты `X.Y` с подпунктами и на функции `X.Y.Z` и `а.`. У каждой функции определяется владелец-подразделение.
3. Из раздела «Структура» строятся реестры подразделений и сравниваются.
4. Пункты выравниваются по содержанию. Одинаковые отсекаются сразу (на тестовом наборе около 3/4 пунктов), LLM получает только изменившиеся.
5. Функции сопоставляются. Для каждого кандидата в потерю запускается агент поиска.
6. LLM ищет дубли и конфликты интересов, все ссылки проверяются валидатором.
7. Результат показывается в интерфейсе и выгружается в `report.xlsx` и `report.html`.

## Технологии

Python 3.12, uv, python-docx, pypdf, openpyxl, Streamlit, OpenAI API (Chat Completions, JSON mode, function calling; модель задаётся в `OPENAI_MODEL`, по умолчанию `gpt-4.1-mini`), pytest.

## Архитектура

```
app.py (Streamlit) / cli.py
        │
    pipeline.py ──► loader.py   docx/pdf/xlsx → абзацы
        │       ──► parser.py   абзацы → пункты (Chunk) и функции (Function)
        │       ──► units.py    реестр подразделений, создано/сохранено/упразднено
        │       ──► align.py    выравнивание пунктов по содержанию + diff
        │       ──► functions.py сопоставление функций по владельцам, поиск
        │       ──► llm.py      классификация, агент проверки потерь, дубли/конфликты, вывод
        │       ──► validate.py проверка пунктов и цитат из ответов LLM
        └──► views.py   человекочитаемый вывод и таблицы (общие для интерфейса, Excel и HTML)
             report.py  Excel + HTML
```

LLM никогда не получает документ целиком, а только выровненные фрагменты с номерами пунктов. Отвечает она строго в JSON со ссылками на эти пункты.

## Установка и запуск

Нужен [uv](https://docs.astral.sh/uv/). Если его нет: `pip install uv`.

```bash
uv sync
cp .env.example .env        # впишите OPENAI_API_KEY (без ключа работает офлайн-режим)
uv run streamlit run app.py # веб-интерфейс
```

Командная строка:

```bash
uv run orgscope data/sample/r8.docx data/sample/r9.docx --out out          # с LLM, если есть ключ
uv run orgscope data/sample/r8.docx data/sample/r9.docx --out out --no-llm # без LLM
```

Тесты: `uv run pytest`.

## Как проверить решение

1. `uv run streamlit run app.py`, отметить «Взять тестовый набор», нажать «Сравнить».
2. Вкладка «Вывод» — итог списком по разделам: структура, функции, что требует внимания, изменения текста.
3. Вкладка «Подразделения»: созданы **ДИТААД** и **ДОА** (п. 3.4 новой редакции), сохранены **ДНМ** и **ДККМ**. Вкладка «Руководители и должности»: упразднена должность **«Директор направления внутреннего аудита»** (п. 3.5–3.6 старой редакции).
4. Вкладка «Передача функций»: функции работы с субъектами СВК и «Картой гарантий» **перешли от ДНМ к ДИТААД/ДОА** (п. 5.4.4 → п. 5.3.3).
5. Вкладка «Потери и дубли»: особые права ДНМ из старого п. 5.7 не найдены в новой редакции. С LLM агент проверяет, потеряны они или переформулированы.
6. У каждой находки указаны пункты «было / стало». `uv run pytest` проверяет эти же случаи автоматически.

## Данные и интеграции

- Тестовый набор организаторов: «Положение о внутреннем аудите», редакции 8 и 9, обезличенные (`data/sample/`).
- OpenAI API, ключ берётся из `.env` и в репозиторий не попадает.

## Ограничения

- Парсер рассчитан на документы с нумерацией пунктов вида `X.Y`, `X.Y.Z` и `а.`. Для документов без нумерации нужна другая нарезка.
- Реестр подразделений берётся из пункта с формулировкой «… состоит из …» и перечней «… подчиняются …». Орг-схемы в виде графики не распознаются.
- Сравнение с внешними нормативами и с практикой других операторов (опциональные пункты ТЗ) не реализовано.
- Поиск в агенте лексический, по основам слов, без эмбеддингов.
- Выводы носят рекомендательный характер и требуют проверки ответственным сотрудником.
